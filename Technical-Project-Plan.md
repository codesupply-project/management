# Codesupply project

# Work packages

The work in the project has been divided into four work packages:
* Work Package 1 - Consortium Management 
* Work Package 2 - Open Data Catalogs 
* Work Package 3 - Open Source Analysis Tools
* Work Package 4 - Open Calls 
* Work Package 5 - Ecosystem Dissemination 

Each work package is represented as a Github issue with `issueId` named after `codesupply-t<work package number>`, e.g Work Package 2 is represented as [`codesupply-t2`](https://github.com/codesupply-project/management/issues/69). The `t`, rather than `w` as in Work Package, is used to make the tasks and sub tasks easier to track.

# Tasks

## Top level tasks (Work Package) 

Each task relates to a work package, e.g.:
* top level task [`codesupply-t2`](https://github.com/codesupply-project/management/issues/69) corresponds to (is actually) Work package 2
* task [`codesupply-t2-4`](https://github.com/codesupply-project/management/issues/73) is a sub tack to [`codesupply-t2`](https://github.com/codesupply-project/management/issues/69)
* sub task `codesupply-t2-4-3` 

Each top level task (work package) has lots of meta information, such as

* Assignees - used to keep track of who is/are assigned to the ticket

For project management we will also use the *Planning* data:

* Estimate - a time estimate
* ProjectID - project identifier (Codesupply)
* IssueID - the task identifier. Each task is name `codesupply-<task number>-<sub task>`, e.g. `codesupply-t2-4`
* Iteration - the iteration when the task is planned for
* TargetDate - the deadline for the task
* Priority - the task's priority (currently not in use)
* Actual - the actual time the task took to finish

The taskss may be further divided into smaller sub tasks, in which case the issueid is `codesupply-<task number>-<sub task>-<sub sub task>`, e.g. `codesupply-t2-4-2`

You can find a list of the tasks in Codesupply here: [Tasks View](https://github.com/orgs/codesupply-project/projects/5/views/10).

### Example task

An example task is [Create and deploy an open data catalog of code threats consisting of known vulnerabilities and known malicious open source software packages](https://github.com/codesupply-project/management/issues/73).
